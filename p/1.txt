做一个很好用的工具，跨机器运行shell。就像结婚一样，所以叫 married sh.

背景：
两台机器，其中一台没有公网，或者是嵌入式设备（以下称Alice)，那么介入它的shell比较困难，我们可以借助一台
有网络的设备（以下称Bob)，把Alice的shell绑定到Bob的环境中。

通常我们可以用 ssh -R 之类的来做这样的事，但是，这样的命令依赖于 ssh 命令存在，-R反射ssh 端口也要求Alice
上的ssh服务存在，对于Bob来说这些可能不是问题，但Alice可能是嵌入式设备。

所以我们要做一个非常简单的事情：它类似于ssh -R，但是不直接暴露端口，而是提供一个运行命令的通道。

最少依赖：程序应该只依赖于最少的系统环境，比如libc/pty/sh。不依赖存在复杂的 ssh 环境等。
也不强求有root权限。编译linux版本时，尽量使用 musl libc。

安全设计：本工具需要用双向安全的密码校验。
第一版本： 使用PSK来要求密码安全。密码在认证过程中不暴露给对方，第三方监听到也不能算出密码。你来选一个较好的算法，比如 SRP ？
后续版本考虑更强的双向 RSA 认证。

最终用法
BOB 上运行服务端：
marriedsh daemon [-n bob] [-p THE.PSK] 0.0.0.0:1234

Alice上运行客户端：
marriedsh join [-p THE.PSK] [-n alice] BOB-IP:1234

如果需要运行 Alice 上的命令，可以这样：
ssh 到 bob 机器上，运行命令：
marriedsh console [-n alice] [cmd ...] 
   default cmd: user shell (use login mode, like set argv[0] to -bash), eg: execv("/bin/bash", ["-bash"])
console 应该尽量使用 pty 运行命令，如果嵌入式设备不允许，也可以回退到基本命令模式。

console 与 daemon 之间使用 unix-socket 通信。

以上的 -n 名字可以选，成为无名连接。连接程序会内部生成唯一id。
只有1对1的情况下，不带名字的命令并不会有歧义。
在1对多时，bob端可以列出所有内部id，用id连接。

如果 Bob 上连接了 Alice，还连接了 Clark，不允许 Alice运行Clark上的命令。反之亦然。


保活设计：
程序应该具有最大的保活能力和最少的资源消耗，在Bob死机的情况下，允许Alice长期存活，并隔一段时间探测重连（推荐值5s，嵌入式设备可以配置到更长)
应对TCP链接保活，tcp流允许存在 ping/pong 命令用于保活。推荐每60秒一次。保活由Alice端发起。（因为B端即使知道A挂了也没有操作办法）

更多的配置可以在 ~/.config/marriedsh/config.toml 中配置。
比如： 
是否允许别的机器运行本机命令。（默认是，如果双向都填了否连接就没有意义了）
unix socket路径。
PSK密码 （这样不用在命令行给出）
保活时长等

注意 config.toml 是可选的，如果它不存在，程序用默认值运行。

测试环境：你应该在本地完成测试。
我为你提供了布署环境：
Bob端： ssh machine1
alice端 ssh -p 2200 root@vps2
alice端的网络环境十分差，你可能要多试几次。如果它已经死了，也可以放弃，等我来修。
